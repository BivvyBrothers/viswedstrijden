Proef: vraagt iOS "wachtwoord bewaren"?

Vier varianten. Tik per variant een willekeurige code van 6 tekens in het codeveld en tik Inloggen. Noteer bij welke variant iOS bovenaan vraagt om het wachtwoord te bewaren. Er gaat niets naar een server.

A: zichtbare gebruikersnaam, formulier weg, URL verandert

Zichtbaar username-veld, wachtwoordveld, na Inloggen: formulier uit de pagina en history.pushState.

B: verborgen gebruikersnaam (zoals in de app), formulier weg, URL verandert

Username-veld offscreen, verder als A.

C: zichtbare gebruikersnaam, formulier alleen verborgen, URL blijft gelijk

Als A, maar het formulier wordt alleen verborgen (display:none) en de URL verandert niet.

D: zichtbare gebruikersnaam, echte hash-navigatie

Als A, maar met location.hash (echte hashchange) in plaats van pushState.

E: zichtbare gebruikersnaam, daarna echte herlaad van de pagina

Als A, maar na Inloggen laadt de pagina opnieuw met ?klaar=e in het adres (een nieuw document, zoals een klassieke website). De code komt niet in het adres.

F: code staat al ingevuld (niet getypt), formulier weg, URL verandert

Als B, maar de code is door de pagina ingevuld. Tik alleen op Bewaren. Werkt dit, dan kan de app de code direct na het aanmelden laten bewaren.
